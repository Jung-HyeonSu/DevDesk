## 9. 성능·접근성·UX 품질 목표

- 데스크톱 우선이나 모바일 360px 너비에서도 가로 오버플로가 불필요하게 발생하지 않아야 한다(코드 입력창 자체의 가로 스크롤 제외).
- JSON, SQL, Diff, Regex처럼 무거운 도구를 도구별 lazy-load.
- 사용하지 않는 라이브러리를 홈 페이지에 번들링하지 않는다.
- 검색은 작은 registry를 클라이언트에서 필터링; 백엔드 검색 금지.
- Lighthouse 성능·접근성·SEO 각 **90점 이상 목표**(테스트 환경, 광고 비활성 상태 기준; 실패 시 개선 내용을 기록).
- Core Web Vitals 개선: 정적 콘텐츠, 불필요한 JS 최소화, 폰트/이미지 최적화, CLS 방지.
- 버튼 키보드 접근, 스크린리더 이름, 입력 오류와 상태의 `aria-live` 제공.
- WCAG AA 수준의 충분한 대비를 목표로 한다.
- 콘텐츠 번역으로 레이아웃이 깨지지 않도록 일본어·중국어·영어의 긴 텍스트를 검증한다.
- 네트워크가 불안정해도 이미 로드된 도구의 핵심 계산은 브라우저 내에서 작동한다. 별도 완전 오프라인 PWA 지원은 MVP 필수 아님.
