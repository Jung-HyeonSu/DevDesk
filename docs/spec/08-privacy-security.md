# 상세 요구사항 08 — 개인정보·보안·안정성

> 기존 GOAL.md의 §8를 분리한 문서입니다. 요구사항 본문은 원문을 유지합니다.

## 8. 개인정보 보호·보안·안정성

- 어떤 도구도 입력값을 외부 변환 API로 전송하지 않는다.
- 사용자 입력값·JWT·SQL·패스워드·해시 전 원문을 URL, localStorage, sessionStorage, 분석 이벤트, 콘솔 로그, 오류 수집 플랫폼에 기록하지 않는다.
- `localStorage` 허용 데이터: theme, 선택 locale, 즐겨찾기 toolId, 최근 방문 toolId 등 비민감 설정.
- 외부 라이브러리 사용 전 라이선스/보안 취약점/번들 크기 점검.
- 입력을 React 텍스트 노드로 렌더하고 임의 `dangerouslySetInnerHTML` 금지(필요한 경우 검증된 sanitizer 필수).
- `eval`, 사용자 코드 실행, SQL 실행, 원격 URL fetch, 비밀번호 검증 서버 등은 제공하지 않는다.
- XSS·ReDoS·YAML alias bomb·큰 입력으로 인한 메모리 문제를 고려한다.
- 라이브러리가 정확히 처리하지 못하는 유형은 안전하게 오류로 처리.
- Web Worker 종료/타임아웃 시 UI가 복구되어 다음 요청을 정상 처리해야 한다.
- HTTP 요청 로그 등 정적 호스팅 사업자가 처리하는 데이터와 광고/분석 서비스가 수집하는 데이터의 존재를 무조건 부정하지 않는다.
- 광고가 활성화될 때는 법령·Google 정책에 맞는 최신 개인정보/쿠키 고지 및 필요한 동의 절차를 운영자가 구성할 수 있도록 문서화한다.
- `contact` 페이지는 임의 이메일을 만들어 넣지 않는다. 환경설정에 운영자 연락처가 있으면 mailto 안내, 없으면 출시 전에 보완해야 할 설정으로 명확히 표시한다.
- 개인정보처리방침과 약관은 **실제 동작하는 서비스 구조를 반영한 초안**으로 작성하며, 광고를 켜기 전 법적 검토가 필요함을 DEPLOYMENT.md에 표시한다.
