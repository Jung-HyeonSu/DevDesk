# 상세 요구사항 07 — 광고 수익화

> 기존 GOAL.md의 §7를 분리한 문서입니다. 요구사항 본문은 원문을 유지합니다.

## 7. 광고 수익화 설계 — 초기에는 비활성화

### 7.1 원칙

- 광고는 **AdSense 승인 후에만** 실제 계정 설정을 추가하고 활성화한다.
- 승인되지 않은 Publisher ID 또는 가짜 광고 코드를 만들지 않는다.
- 작업 영역의 입력·출력, 실행 버튼, 복사/다운로드 버튼 바로 옆·사이에 광고를 끼워 넣지 않는다.
- 광고임을 명확히 알 수 있고 탐색/다운로드 버튼과 혼동되지 않도록 한다.
- 광고 로딩에 따른 화면 이동(CLS)을 방지할 공간 예약 정책을 마련한다.
- 광고 차단 환경에서도 모든 도구가 오류 없이 작동해야 한다.
- 초기 페이지는 도구 기능과 자체 가이드 콘텐츠가 중심이며, 광고를 보여주기 위한 빈 페이지를 생성하지 않는다.

### 7.2 기술 구현

- 재사용 가능한 `<AdSlot placement="..." />` 컴포넌트를 설계.
- `NEXT_PUBLIC_ADSENSE_CLIENT_ID` 등 **공개 가능한 광고 식별자**만 빌드 타임에 설정.
- 값이 없거나 활성화 스위치가 false면 광고 스크립트를 로드하지 않고 개발자 콘솔 오류도 없어야 한다.
- 빌드 시 사용되는 공개 설정만 허용하며 비밀 API 키를 번들에 포함하지 않는다.
- 지역별 개인정보·동의 정책을 충족할 수 없으면 해당 범위의 광고를 활성화하지 않는다.
- 광고·분석 스크립트는 외부 네트워크 통신이 발생한다는 사실을 개인정보처리방침에 반영.
- 승인 전 `ads.txt`는 실제 계정 정보가 없으면 잘못된 내용을 생성하지 않는다. 운영자가 계정에서 제공받은 값을 나중에 추가하도록 README에 안내.

### 7.3 배치 후보

1. 도구 UI 아래, 가이드 설명 이전의 광고 영역 1개.
2. 충분한 본문 콘텐츠 이후 광고 영역 1개(승인 및 정책 검토 후).
3. 모바일 화면에서는 입력/출력 사이 삽입 금지.

> 수익은 트래픽·지역·광고 수요·사이트 승인 등에 의존하므로 고정 수익을 약속하지 않는다.
