# 상세 요구사항 16 — 콘텐츠 품질 및 편집 운영

## 목적

DevDesk의 콘텐츠는 광고 노출이나 검색어 수집보다 개발자가 작업을 끝내도록 돕는 데 목적이 있다. 승인 여부, 검색 순위, 트래픽을 약속하지 않는다.

## 워크플로 가이드 품질 기준

- 하나의 실제 개발 과제를 중심에 두고, 한 도구의 기능 목록을 여러 페이지로 복제하지 않는다.
- 가상임을 표시한 입력과 기대 결과를 제공해 독자가 절차를 재현할 수 있게 한다.
- 단계를 단순 나열하지 말고, 각 도구의 결과를 어떻게 읽고 다음 확인으로 이어갈지 설명한다.
- 도구가 확인할 수 없는 것(예: JSON 포맷 성공이 스키마 유효성을 증명하지 않음, JWT 디코딩이 서명 검증이 아님)을 명시한다.
- 중요한 기술 설명에는 표준이나 공식 문서처럼 확인 가능한 출처를 연결한다. 출처의 내용을 복사하는 대신 독자의 문제 해결에 필요한 의미를 요약한다.
- 개인정보·자격 증명 주의사항은 구체적으로 쓴다. 브라우저 내 처리가 운영 토큰이나 개인 정보의 무분별한 입력을 정당화하지 않도록 한다.

## 다국어 및 유지관리

- 한국어, 영어, 일본어, 중국어 간체에서 모든 단계·제약·예제가 일관된 의미를 가져야 한다.
- 직역으로 어색한 문장은 해당 언어 개발자가 이해하기 쉬운 표현으로 다듬는다. 사실, 단위, API 이름, 표준 식별자는 보존한다.
- 표준 또는 도구 동작이 바뀌었을 때만 내용을 갱신하고, 실질적인 수정 없이 날짜를 바꿔 최신처럼 보이게 하지 않는다.
- 검토 시 링크 유효성, 도구 동작과 예제 일치, 내부 연결, 페이지 간 중복을 함께 살핀다.
- 도구 상세 페이지와 실질적으로 같은 본문을 가진 레거시 URL은 도구 상세 페이지를 canonical로 지정하고 색인 대상에서 제외한다. sitemap과 내부 링크에는 독창적 콘텐츠 URL만 둔다.
- 사용자가 실제로 관심을 보인 주제는 Search Console 등 운영 자료를 확인해 우선순위에 반영한다. 계정 연결 전에는 사용량이나 재방문을 추정치로 기록하지 않는다.
- 홈과 도구별 가이드 색인에 동일한 워크플로 모음이나 홍보 카드를 반복하지 않는다. 독창적인 워크플로 문서는 관련 도구 페이지와 sitemap에서 찾을 수 있게 유지하고, 가이드 색인은 도구별 사용 참조에 집중한다.
- 새 도구는 단순 입력창에 그치지 않고 재현 예제, 결과를 읽는 방법, 지원 범위·한계, 오류 설명, FAQ와 공식 표준·문서 링크를 제공한다. 변환·검사 결과가 증명하지 않는 사실도 명시한다.
- 워크플로 조립기 레시피는 한 가지 실무 과제를 시작부터 결과 판독까지 연결한다. 레시피 설명만 바꾼 중복 페이지나 도구 설명 복사로 분량을 채우지 않는다.
- 번역별 페이지 수는 품질 지표가 아니다. 각 언어에서 입력·예상 결과·주의사항이 일치하는지 확인하고, 기술 식별자와 공식 출처 링크는 정확하게 유지한다.

## 금지할 편집 방식

- 키워드만 바꾼 유사 페이지를 대량으로 추가하지 않는다.
- 검색 순위 조작을 목적으로 자동 생성하거나, 출처를 바꿔 쓰거나, 설명을 분량만 늘리지 않는다.
- 존재하지 않는 저자 경력·사용 경험·검증 결과·사용자 통계를 만들어내지 않는다.
- 콘텐츠 개선을 AdSense 승인 보장으로 표현하지 않는다.
